# 内置 QQ 机器人

本 fork 将 `astrbot_plugin_newapi` 的功能迁移为 new-api 内置的 Go 机器人，不再依赖 AstrBot。机器人随镜像发布，NapCat 通过 OneBot 11 反向 WebSocket 直接连接 new-api。

## 配置

1. 在「系统设置 → 运维 → QQ 机器人」填写机器人 QQ 号、连接密钥（至少 16 个字符）和绑定的会话，然后启用。
2. 在 NapCat 中添加 WebSocket 客户端（反向 WS）：地址 `ws://<new-api>:3000/onebot/v11/ws`，token 填连接密钥，消息格式使用 `array`。

配置保存在现有 options 中（`qq_bot.*`），修改后无需重启；不新增数据库表或字段。`qq_bot.ws_secret` 不会通过 `GetOptions` 返回给前端。

绑定的会话每行一个，`=分组` 可选：

```text
group:123456
group:234567=paid
private:10001
```

## 命令

以下以默认前缀 `newapi` 为例，前缀可通过 `qq_bot.command_prefix` 修改。只有绑定的会话可以执行，不区分发送者：

- `/newapi`：帮助；未知子命令同样返回帮助
- `/newapi quota [all] [allgroup]`
- `/newapi flow [30m|1h|7d] [allgroup]`
- `/newapi on|off <渠道 ID>`
- `/newapi weight|priority <渠道 ID|all> <数值>`

群聊和私聊都必须以 `/` 开头才能唤醒，@ 机器人不会唤醒。未绑定的会话不会收到任何回复，包括帮助。会话标识直接按 QQ 群号或 QQ 号填写，不提供 `/sid` 的替代命令。

## 与插件的配置对应

| 插件 | 内置机器人 |
| --- | --- |
| `instances[].umos`、`group_filters` | `qq_bot.sessions` |
| `instances[].hidden_groups` | `qq_bot.hidden_groups` |
| `instances[].flow_stages` | `qq_bot.flow_stages`，默认改为 `user,model,channel` |
| `instances[].user_id` | `qq_bot.user_id`，仅用于审计归属 |
| `flow_hours`、`flow_top_n`、`flow_overflow`、`request_timeout`、`font_path` | 同名 `qq_bot.*` |
| `instances[].base_url`、`access_token`、`name` | 不再需要 |

## 行为差异

- 唤醒规则比 AstrBot 更严格：私聊不能省略 `/`，@ 也不能唤醒；未绑定的会话完全静默。
- 不再支持一个机器人管理多个 new-api 实例：每个部署各有一个机器人，NapCat 可以配置多个 WS 客户端分别连接。同一部署只接受一个连接，多节点时只让 NapCat 连接其中一个节点。
- 流图左侧默认从令牌改为用户，因为现在每人使用独立用户而不是共用管理员和不同 API Key。
- 命令以 root 角色在进程内执行，`token`、`node` 阶段始终可用，不再依赖 Access Token 的权限。
- 回复与图片沿用插件的中文文案，未接入 `i18n.T`。

## 实现

- `qqbot/onebot`：反向 WebSocket 传输，单连接；握手校验密钥与 `X-Self-ID`，再用 `get_login_info` 确认登录账号。
- `qqbot/render`：纯 Go 绘图（`golang.org/x/image`），版式移植自插件的 Skia 实现。
- `qqbot`：命令与额度归一化。`newAPIEngine` 在私有 gin engine 上挂载现有管理接口，命令在进程内调用，因此保留原有校验、渠道缓存刷新、WebSocket 断开和审计日志，也几乎不改动上游文件，便于 rebase。审计日志的 `admin_username` 记录为 `qq:<发送者>`。
- 镜像增加 `fonts-noto-cjk`（Debian bookworm 中为 `/usr/share/fonts/opentype/noto/NotoSansCJK-{Regular,Bold}.ttc`）。

## 安全

参考 OWASP [Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)：

- 连接密钥由服务端校验，比较 SHA-256 摘要并使用常量时间比较；不记录日志，也不返回前端。
- 未启用或未配置时端点返回 404；端点受全局 API 限流保护，以限制猜测。
- 轮换密钥或关闭机器人后，已有连接在收到下一帧时断开（多节点受 options 同步周期影响）。

已知缺口：授权模型沿用插件，绑定群内任何成员都可以启停渠道和修改路由；连接密钥与其他 options 一样以明文保存在数据库中。

## 验证

- 同一组数据分别用插件的 Skia 代码和 Go 渲染：图片尺寸一致，强差异像素约 0.56%（额度图）和 0.08%（流图），均为文字抗锯齿。
- 用真实 new-api 二进制、SQLite、模拟 NapCat 和模拟 Codex 上游跑了端到端检查：鉴权拒绝、错误登录账号、第二连接、唤醒规则、自定义前缀、未绑定会话静默、绑定与分组过滤、全部命令、数据库写入、审计日志、密钥轮换。
- 在浏览器中保存设置并用保存的密钥完成连接。
- 按本 fork 约定未提交单元测试。未使用真实 NapCat 验证，也未完整执行 `docker build`。
