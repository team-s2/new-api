# 内置 QQ 机器人

本 fork 将 `astrbot_plugin_newapi` 的功能迁移为 new-api 内置的 Go 机器人，不再依赖 AstrBot。机器人随镜像发布，以 QQ 官方机器人的身份由主节点连接 QQ 网关，不再需要 NapCat。

## 配置

1. 在 [QQ 开放平台](https://q.qq.com/) 创建机器人，取得 AppID 与 AppSecret，并把机器人加入要使用的群。
2. 在「系统设置 → 运维 → QQ 机器人」填写 AppID、AppSecret，然后启用。主节点会连接 QQ 网关。
3. 在要使用的群里 @ 机器人发送 `id`，机器人会回复这个群的绑定行，例如 `group:0123456789ABCDEF0123456789ABCDEF`。把它加入「绑定的会话」并保存。

配置保存在现有 options 中（`qq_bot.*`），修改后无需重启；不新增数据库表或字段。`qq_bot.app_secret` 不会通过 `GetOptions` 返回给前端。

绑定的会话每行一个群，`=分组` 可选。QQ 官方机器人只提供每个机器人独有的 openid，不提供群号：

```text
group:<群 openid>
group:<群 openid>=paid
```

从 NapCat 版本升级时，旧的 `qq_bot.self_id`、`qq_bot.ws_secret`、`qq_bot.command_prefix` 不再使用，按群号或 QQ 号填写的旧绑定也不再匹配，需要按上面的步骤重新绑定。与 pigapi 一致，机器人只服务群聊，不再支持私聊，旧的 `private:` 绑定会被拒绝。不再使用的旧 key 仍按原值留在 options 表中（包括明文的 `ws_secret`），代码不再读取，介意的部署可以手动删除这些行；若升级前 `enabled` 为 true 但尚未填 AppID/AppSecret，开关保持启用而机器人不会连接，填齐凭据后即按预期连上。

## 命令

在群里 @ 机器人后跟子命令；子命令前的 `/` 可选，便于在 QQ 开放平台注册指令。只有绑定的群可以执行，不区分发送者：

- `@机器人`：帮助；未知子命令同样返回帮助
- `@机器人 id`：回复当前会话的绑定行；未绑定的会话也会回复
- `@机器人 quota [all] [allgroup]`
- `@机器人 flow [30m|1h|7d] [allgroup]`
- `@机器人 on|off <渠道 ID>`
- `@机器人 weight|priority <渠道 ID|all> <数值>`
- `@机器人 peak <渠道 ID> on|off`：开关智谱 Coding Plan 渠道的高峰期自动禁用（周一至周五 14:00-18:00 UTC+8）

未绑定的会话除 `id` 外不会收到任何回复。群里不 @ 机器人的消息一律忽略。

## 与插件的配置对应

| 插件 | 内置机器人 |
| --- | --- |
| `instances[].umos`、`group_filters` | `qq_bot.sessions`，会话标识改为 openid |
| `instances[].hidden_groups` | `qq_bot.hidden_groups` |
| `instances[].flow_stages` | `qq_bot.flow_stages`，默认改为 `user,model,channel` |
| `instances[].user_id` | `qq_bot.user_id`，仅用于审计归属 |

| `instances[].base_url`、`access_token`、`name` | 不再需要 |

## 行为差异

- 只服务群聊，必须 @ 机器人才能唤醒；私聊消息一律忽略。未绑定的群除 `id` 外完全静默。
- 回复都是 QQ 的被动回复：平台窗口为用户消息后 60 分钟、每条消息最多回复 5 次，多次回复使用递增的 `msg_seq`。实现仍把命令整体时限保守地控制在 4 分钟，避免聊天命令长时间悬挂，超时也能在窗口内告知失败。
- 主动消息（重置卡领取通知、高峰期通知）需要 QQ 开放平台授予主动消息权限；未授权时接口返回 `40034105 主动消息失败, 无权限`，机器人只记录日志，不补发。
- QQ 只允许每个机器人保持一个网关会话，因此只有主节点连接；从节点不运行机器人。注意 new-api 里 `NODE_TYPE` 不是 `slave` 的进程都是主节点，部署时必须保证只有一个主节点进程，否则多个网关会话互相挤掉、反复重连丢消息。
- 不再支持一个机器人管理多个 new-api 实例：每个部署使用各自的 QQ 机器人。
- 流图左侧默认从令牌改为用户，因为现在每人使用独立用户而不是共用管理员和不同 API Key。
- 命令以 root 角色在进程内执行，`token`、`node` 阶段始终可用，不再依赖 Access Token 的权限。
- 回复与图片沿用插件的中文文案，未接入 `i18n.T`。

## 实现

- `qqbot/official`：QQ 官方机器人传输。用 AppID 与 AppSecret 换取 app access token 并缓存到过期前一分钟；OpenAPI 走当前统一域名 `api.bot.qq.com`，业务错误码同时兼容 `err_code` 与旧的 `code` 字段。主节点经 `/gateway` 连接网关，订阅群消息事件（intent `1 << 25`，QQ 把单聊事件放在同一个 intent 中，机器人忽略它们），处理心跳、`op 7` 重连与 `op 9` 失效会话（`d` 为 true 时仍可 resume），禁用或更换凭据后在下一次心跳断开。断线重连按 QQ 关闭码决定恢复方式：网络中断、`4008`、`4009` 保留会话并 resume，`4006`、`4007` 与 `4900-4913` 清空会话重新 identify；resume 重放的遗漏事件在 `RESUMED` 之前到达，照常处理并按消息 ID 去重。群消息同时接受 `GROUP_AT_MESSAGE_CREATE` 和 `GROUP_MESSAGE_CREATE`：开通了接收全部群消息的机器人只会收到后者，此时只处理 `mentions` 中 `is_you` 的消息并去掉 `<@openid>`。按消息 ID 去重，避免 resume 或两类事件重复投递。图片先上传到 `/v2/groups/<openid>/files`，再以 `msg_type 7` 与说明文字一起发出。
- `qqbot/render`：纯 Go 绘图（`golang.org/x/image`），版式移植自插件的 Skia 实现。
- `qqbot`：命令与额度归一化。`newAPIEngine` 在私有 gin engine 上挂载现有管理接口，命令在进程内调用，因此保留原有校验、渠道缓存刷新、WebSocket 断开和审计日志，也几乎不改动上游文件，便于 rebase。审计日志的 `admin_username` 记录为 `qq:<发送者 openid>`。
- 镜像增加 `fonts-noto-cjk`（Debian bookworm 中为 `/usr/share/fonts/opentype/noto/NotoSansCJK-{Regular,Bold}.ttc`）。

## 安全

参考 OWASP [Secrets Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)：

- AppSecret 只用于向 `bots.qq.com` 换取 access token，不记录日志，也不返回前端；access token 只保存在内存中。
- new-api 不再暴露任何机器人入站端点，消息来源由 QQ 网关会话保证。
- 关闭机器人或更换 AppSecret 后，已有网关会话在下一次心跳（约 40 秒）时断开。

已知缺口：授权模型沿用插件，绑定会话内任何成员都可以启停渠道和修改路由；AppSecret 与其他 options 一样以明文保存在数据库中。

## 验证

- 同一组数据分别用插件的 Skia 代码和 Go 渲染：图片尺寸一致，强差异像素约 0.56%（额度图）和 0.08%（流图），均为文字抗锯齿。
- 2026-11-24 使用测试机器人 botling 和真实 QQ 群，在本地 new-api（SQLite）上验证：网关连接与心跳、`GROUP_MESSAGE_CREATE` 的 @ 识别与不 @ 时忽略、未绑定会话仅响应 `id`、绑定后的帮助、`quota`、`off 1`/`on 1`（图片与说明同一条消息）、字体路径配置；同一消息重复使用 `msg_seq` 被 QQ 以 `40054005` 拒绝，主动消息在未授权时返回 `40034105`。未验证主动消息授权后的行为。注意这次实测走的是旧域名 `api.sgroup.qq.com`；之后代码按当前文档与 pigapi 改用统一域名 `api.bot.qq.com`，行为一致但尚未再用真实机器人回归。
- 2026-11-25 用本地假网关（TLS + 改写的 RoundTripper/Dialer）验证了修复后的会话恢复语义，覆盖：resume 重放事件在 `RESUMED` 之前到达也会处理、关闭码 `4009` 保留会话并 resume、`4006` 清空会话重新 identify、`op 9` 的 `d` 为 true 保留会话、false 重新 identify、重放的重复消息按 ID 去重不重复执行、全量群消息仅 `is_you` 提及才处理、图片上传携带 `file_name`。按本 fork 约定验证后删除了这些临时测试，未提交单元测试。

## 重置卡领取通知

主节点每 5 分钟检查智谱重置卡领取任务，遵循上游冷却时间；成功领取后向符合渠道分组过滤条件的绑定群发送主动消息，内容为渠道名称、ID 及领取前后库存增加的5小时卡、周卡数量；库存查询失败或差值异常时提示数量暂时无法确认。同一轮领取结果合并通知，不自动用卡。未获得主动消息权限或发送失败时仅记录日志，不补发。
